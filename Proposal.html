Internship Project Proposal

Smart AgriTech Mesh Network

A High-Availability Hybrid Mesh & Edge Gateway designed for Egypt's smart greenhouse and poultry farm sectors. Proposed to Syntax-IoT Engineering Team.

Executive Summary

In Egypt's agricultural settings—specifically poultry farms and greenhouses—stable wireless coverage is consistently hampered by dense crop canopies, structural metal framing, and remote locations with poor cellular signals.

The **Smart AgriTech Mesh Network** is designed as an infrastructure-agnostic, low-cost solution. Using a local Layer 2 wireless mesh (ESP-NOW), the system gathers multi-zone telemetry, acts on it with local edge logic, and handles cellular backhaul outages without data loss.

Key Value Propositions

  • Self-Healing Local Coverage: Overcomes physical obstructions without requiring expensive cabling.
  • Battery-Powered Longevity: Advanced power management allows child sensors to run up to 2 years on a single 18650 cell.
  • Zero Data Loss Pipeline: In-memory and flash storage buffers data locally when cellular backhaul fails.
  • Decoupled Edge Logic: Direct node-to-node actuation ensures active cooling or watering runs offline.

Starter Topology (Proof of Concept)

To demonstrate the project feasibility, we will initiate a four-node network:

  • 1x Master Node (Gateway): Cell-connected (SIM800L), coordinates mesh updates, stores offline buffers.
  • 1x Actuator Node (Router): Mains-powered, triggers high-power equipment, routes signals.
  • 2x Sensor Nodes (SHT31 Nodes): Runs baseline climate monitoring (Temp & Hum), with optional pH input.

This minimum configuration directly demonstrates routing around barriers, network collision handling, and edge loop feedback control.

System Architecture

The system operates on an offline-first hierarchy. If connection to the cloud or Syntax-IoT dashboard is lost, the local mesh operates autonomously.

Gateway Core (Master Node) Blueprint

The Master Node serves as the nervous system coordinator and cloud boundary of this network architecture. Designed to handle local operations offline, it buffers sensor readings and manages the network structure dynamically.

Hardware Schematic & Connections

To ensure high current stability and clean RF signals, the following peripheral mapping and circuit design are enforced:

ESP32 GPIO17 (TX2) → SIM800L: SIM800L RX (Via Resistor Divider: 10k & 20k)
ESP32 GPIO16 (RX2) → SIM800L: SIM800L TX (Direct Connection)
ESP32 GPIO4 (RST) → SIM800L: SIM800L Reset pin (Hard power reset control)
I2C SSD1306 OLED (SDA/SCL): ESP32 GPIO21 (SDA) & GPIO22 (SCL)
Power Outage Detection: ADC pin GPIO34 connected to 5V line divider
GSM Voltage Regulator (LM2596): Voltage output tuned to exactly 4.0V DC (Vcc input to module)
Power Filter Bank: 1000µF Low-ESR Capacitor across SIM800L VCC/GND

Note: The SIM800L utilizes a 2.8V CMOS logic level. Routing a 3.3V UART signal directly from the ESP32 TX line requires a simple 2:3 voltage divider to prevent module RX damage.

Dual-Core Firmware Task Division

The Master Node leverages the ESP32’s dual-core Xtensa processor running FreeRTOS to execute networking and radio tasks simultaneously:

CORE 0: Local Mesh Radio (ESP-NOW)

  • Initializes ESP-NOW protocol stack.
  • Runs active RX listening loop to receive incoming sensor telemetry.
  • Decrypts and validates packet signatures.
  • Sends immediate hardware-level ACKs to sleepy child nodes.

CORE 1: Cloud Uplink & Local Decisions

  • Maintains MQTT client state over SIM800L GPRS.
  • Pushes queues to the Syntax-IoT database (when online).
  • Manages the LittleFS data queue during offline states.
  • Runs the local threshold rules logic (triggering actuators).

Master MCU FreeRTOS Tasks & IPC Implementation Blueprint

To guarantee high system responsiveness, the firmware must partition its scheduler into discrete, prioritized FreeRTOS tasks. Communication between tasks on different cores is managed using thread-safe queues and mutexes.

Task Handle Name Target Core Priority Stack Size Responsibility IPC Interface Used
vTaskMeshReceiver Core 0 5 (High) 4096 Bytes Wakes up instantly on ESP-NOW packet interrupt callbacks. Reads the packet data and parses it. Pushes to xTelemetryQueue
vTaskMeshBroadcaster Core 0 2 (Low) 2048 Bytes Wakes up periodically (e.g. every 60s) to broadcast the RTC synchronization beacon to the mesh. Uses shared clock variable
vTaskCloudUplink Core 1 3 (Normal) 8192 Bytes Pops telemetry from the queue. If GPRS is connected, uploads to cloud. If offline, stores to flash. Pulls from xTelemetryQueue, locks xFlashMutex
vTaskRulesEngine Core 1 4 (Normal-High) 4096 Bytes Inspects sensor data in real-time. Sends direct command packets to routers if threshold levels are violated. Reads from xTelemetryQueue
vTaskOfflineSync Core 1 1 (Lowest) 4096 Bytes Periodic check (e.g. every 10 min). If online, reads buffered data out of flash and uploads it. Locks xFlashMutex
vTaskDiagnosticHMI Core 1 1 (Lowest) 3072 Bytes Executes every 500ms to update OLED stats and toggle diagnostic LED indicators. Global status flags

1. Telemetry Queue (xTelemetryQueue)

A thread-safe FreeRTOS queue holding up to 50 items. It acts as the pipeline between the Core 0 radio thread and the Core 1 application threads. This prevents packet drops even if the GPRS stack blocks Core 1 during a network socket negotiation.

2. Flash Mutex (xFlashMutex)

A binary semaphore (mutex) protecting the LittleFS file system partition. Since the vTaskCloudUplink task (writing new logs when offline) and vTaskOfflineSync task (reading and deleting logs when online) run asynchronously, the mutex guarantees file descriptors do not get corrupted.

High-Availability & Crash Recovery Features

1. Anti-Lockup SIM800L Watchdog

SIM800L cellular modules frequently hang due to network carrier drops on 2G. The ESP32 firmware monitors AT command pings. If the module stops responding to `AT\r` pings for more than 30 seconds, the ESP32 pulls the SIM800L Reset line (GPIO4) low for 100ms, performing a hard reset of the cellular connection.

2. Power Outage State-Save

Agricultural power grids in Egypt are prone to voltage drops. By placing a voltage divider from the mains 5V DC line into the ESP32 ADC (GPIO34), the processor constantly monitors input voltage. If it detects a drop below 4.5V, it immediately suspends non-essential tasks, writes remaining in-memory telemetry queues to the flash file system (LittleFS), and cleanly closes file system handles before power is fully lost.

3. Self-Healing Routing Sync

If a router node (Actuator) fails, the master coordinates with sleeping child nodes to modify their static address routing. If they fail to receive an ACK from their primary router, they fall back to broadcasting their payload to find alternative paths to the Master.

Sensor Core (SHT31 / pH Node) Blueprint

To optimize for low power and high reliability, the sensor node defaults to an SHT31-only climate monitor. For water quality tracking in hydroponics or fish farms, the board includes a modular, optional **pH sensing expansion kit**.

Base Configuration: SHT31-D (Climate)

The baseline configuration is designed for maximum power efficiency using the I2C SHT31-D sensor to monitor ambient temperature and relative humidity:

I2C Pins: ESP32 GPIO21 (SDA) / GPIO22 (SCL)
Deep Sleep Draw: < 15µA (Targets 2-year battery life)
Active Sampling Time: < 1.5 seconds (Wakes, reads I2C, transmits, sleeps)
Protection Mode: Internal heater dries condensation in greenhouses

By keeping the base node SHT31-only, we avoid high power-gating currents and can power the board using a standard 18650 Li-Ion cell and a small solar panel.

Optional Expansion: Analog pH Kit

For hydroponics or aquaculture monitoring, the node can be populated with a **pH-4502C probe** and a **DS18B20 sensor** for temperature compensation:

[pH Sensor Board (5V)] ─── [10k Ohm] ──┬──> ESP32 ADC (GPIO32)
                                       │
                                   [20k Ohm] ──> GND
  • Voltage Divider: Scaler drops the 5V analog pH signal down to the safe 3.3V range of the ESP32 ADC.
  • DS18B20 Compensation: Reads water temperature via 1-Wire (GPIO15) to correct chemical pH drift in real-time.
  • Power Constraint: The pH module runs at 5V, meaning when this kit is connected, the node is best operated with a stable external power adapter.

Engineering Feasibility

Designing this project within the scope of an internship is highly achievable, but demands careful embedded programming. Here is what is immediately feasible:

  • Firmware Framework: Developing on ESP-IDF or Arduino IDE with FreeRTOS simplifies multitasking. Using FreeRTOS queues allows clean division between sensor sampling and wireless transmission tasks.
  • Local Telemetry: Standard sensors (SHT31-D, pH-4502C, DS18B20) have well-tested drivers, making initial integration straightforward.
  • Offline Buffering: Writing a circular flash logger using LittleFS on the ESP32's onboard flash is robust and prevents write failures.

Key Technical Challenges

1. OTA Firmware Updates Over Mesh

Updating child nodes remotely is a key requirement, but transmitting a 1MB firmware binary over ESP-NOW mesh is highly prone to packet loss. We must implement block-wise transfers with negative acknowledgments (NACK) to request missing bytes and prevent node bricking.

2. Severe Egyptian Heat vs. Batteries

In greenhouses and metal poultry barns, temperatures in Egypt's summer can exceed 45°C. Standard Li-Ion batteries degrade rapidly or enter thermal runaway at these temperatures. We must design thermal protection circuits or switch to LiFePO4 cells which tolerate higher operational limits.

3. Signal Attenuation in High Moisture

Greenhouses packed with high-moisture foliage act as 2.4GHz RF dampeners. To counter this, physical antenna design (using external RP-SMA antennas instead of onboard PCB trace antennas) is mandatory for reliable mesh propagation.
